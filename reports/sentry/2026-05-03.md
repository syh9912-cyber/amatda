**Root cause hypothesis**:  
`checkForUpdateAsync()` is called unconditionally 2 seconds after app start (`useOTAUpdate` hook in `app/_layout.tsx:154`). When the device has no network connection (`online: false` confirmed in event context), the native `ExpoUpdates` module rejects the promise with `Failed to check for update`. The catch block at line 139 calls `captureError()` unconditionally, sending the error to Sentry even though this is an expected offline condition.

**Why not auto-fixed**:  
The fix requires a meaningful logic change to the async startup flow — either:
1. Add a `NetInfo.fetch()` pre-condition guard before calling `checkForUpdateAsync()` (introduces a new async call in the startup chain), or  
2. Inspect the caught error in the catch block and skip `captureError` for network errors (requires defining what qualifies as a network error).  
Neither maps cleanly to the auto-fix categories (typo / null guard / missing import / type annotation), and both touch app bootstrap logic where a mistake could silently break OTA delivery.

**Suggested action**:  
Add an early-exit guard in `checkAndApply()` (`app/_layout.tsx:101`) using the already-installed `@react-native-community/netinfo` (v11.4.1):

```typescript
import NetInfo from '@react-native-community/netinfo';
```

This prevents the error from being thrown in the first place and keeps Sentry clean for genuine OTA failures. No new dependency needed.
