### 1. sylabs.kr 웹사이트에서 관리자 화면 접속이 차단됨
- **얼마나 자주 발생하나**: 7월 19일 오전 9시 07~08분 사이 3번 발생
- **어떤 상황에서 발생하나**: `sylabs.kr` 주소에서 관리자 사용자 목록 조회(`/api/admin/users`)를 요청할 때, 서버가 "허가되지 않은 출처"라며 차단
- **사용자가 실제로 겪는 것**:  
  🟡 **보통** — 관리자가 `sylabs.kr` 웹페이지에서 관리 기능을 사용하려 할 때 연결이 막힘. 실제 앱 사용자에게는 영향 없음
- **왜 이런 일이 생겼나**:  
  서버에 현재 배포된 코드는 접속 허용 주소 목록에 `sylabs.kr`이 없습니다.  
  그런데 지금 개발 소스에는 이미 이 주소를 허용하도록 수정이 되어 있습니다.  
  즉 "코드는 고쳐졌지만, 서버에 아직 올리지 않은 상태"가 원인입니다.
- **추천**: 🔧 **고치는 게 좋음**
- **추천 이유**: `sylabs.kr`이 SY Labs 공식 도메인으로 관리자 도구를 구축하려는 의도라면, 현재 소스의 수정 내용을 서버에 배포하면 해결됩니다. 단, `sylabs.kr`이 관리자 용도가 맞는지 확인이 먼저 필요합니다.
- **고친다면 이렇게**:
  - 확인 후 백엔드 재배포만 하면 해결됨 (소스 코드는 이미 수정되어 있음)
  - 사장님이 Claude 에게 시킬 말 예시: `"백엔드 CORS 수정 내용 배포해줘. sylabs.kr 관리자 접속 허용해야 해."`

### 2. 소셜 로그인(카카오·구글·네이버·애플) 외부 탐침 트래픽 감지
- **얼마나 자주 발생하나**: 7월 18일 오후 12시 34~35분 1분 사이에 27번 집중 발생  
  (카카오 앱 ID 오류 5회, 카카오 코드 교환 실패 4회, 네이버 검증 실패 8회, 구글 검증 실패 4회 + 과거 누적 16회, 애플 형식 오류 3회, 구글 누적 16회)
- **어떤 상황에서 발생하나**: 미국 서버에서 잘못된 로그인 코드(`code=bad_diag` 등 명백히 가짜 값)를 이용해 로그인 서버를 자동으로 두드려보는 시도
- **사용자가 실제로 겪는 것**:  
  🟢 **가벼움** — 실제 앱 사용자에게 영향 없음. 앱 서버가 이 시도들을 모두 정상적으로 거부함. 로그만 쌓임
- **이것이 진짜 문제인가**:  
  앱 자체는 아무 문제 없이 동작 중입니다. 인터넷에서 흔히 발생하는 "자동 탐색 로봇(봇)"이 로그인 창을 두드려보는 것이며, 앱이 올바르게 막아냈습니다.  
  다만 이런 시도가 반복될 경우를 대비해 모니터링 필요.
- **추천**: ✅ **그냥 둬도 됨** (단, 빈도가 늘면 재검토)
- **추천 이유**: 서버가 모두 정상 거부 중이며, 실제 피해가 없습니다. 인증 요청에는 이미 15분 30회 제한이 걸려 있어 대량 공격에 대한 방어가 되어 있습니다.
- **고민이라면**:
  - 수정할 파일: `backend/src/middleware/security.ts`
  - 수정 방향: 인증 요청 속도 제한(현재 15분 30회)을 더 강하게 조이거나, IP 차단 규칙 추가 검토
  - 사장님이 Claude 에게 시킬 말 예시: `"소셜 로그인 봇 차단 강화해줘. 인증 엔드포인트 rate limit 더 엄격하게 설정해줘."`
